# WhiteRoom Storyboard Tag Specification

## Purpose

Text files loaded in the Text Reader can embed **storyboard tags**: special standalone lines that trigger image and effect changes as the reader advances.

Storyboard tags let a text file drive the visual state of all cells. They can switch the displayed image, apply partial effect overrides, ramp effects across multiple pages, and optionally start the timer when a tagged segment becomes active.

## Tag Format

Tags must occupy their own line. They are stripped from the displayed reader text and fire when the **next clean paragraph** first becomes visible.

### Type 0: Reading Config Tag

The reading config tag is a special tag stored on the **very first line** of the file. It is generated by the "Save Reading Settings" button in the Storyboard tool and is automatically applied when the file is opened.

```text
[WR-RC:1.5.2:{"windowSize":{"width":1600,"height":1000},"textReader":{...},"showControls":true}]
```

Format:

```text
[WR-RC:<appVersion>:<JSON payload>]
```

JSON schema:

```typescript
{
  windowSize: { width: number; height: number }
  textReader: TextReaderConfig   // window position, font, speed, etc.
  showControls: boolean          // UI panel show/hide state
}
```

Field notes:

- `windowSize` is the full frame size of the Electron window at the time the button was pressed. Restored via `BrowserWindow.setSize()`.
- `textReader` contains the full `TextReaderConfig` snapshot. Merged with defaults on restore so forward-compatible with new fields.
- `showControls` records whether the right-side control panel was visible.
- This tag is not a storyboard trigger — it does not fire on page advance. It is read once when the file loads.
- Only one reading config tag is allowed per file. Clicking "Save Reading Settings" again replaces the existing tag in place.
- The tag must be on line 1 (index 0). Any leading blank lines between it and the first paragraph are ignored.
- Unlike storyboard trigger tags, this tag is **not** included in `tagEntries` and does not affect `segmentStartLines`.

### Type 1: Simple Tag

Simple tags are intended to be easy to write by hand:

```text
[[C:\path\to\image.jpg]]
```

Behavior:

- Switches the displayed image on all cells.
- Does not change effects.

### Type 2: Rich Tag

Rich tags are app-generated by the Storyboard tool:

```text
[WR:1.4.0:{"image":"C:\\path\\image.jpg","effects":{...},"progress":{"enabled":true,"pages":5},"timer":{"enabled":false}}]
```

Format:

```text
[WR:<appVersion>:<JSON payload>]
```

JSON schema:

```typescript
{
  image: string
  effects: Partial<CellEffects>
  progress?: { enabled: boolean; pages: number }
  timer?: { enabled: boolean }
}
```

Field notes:

- `image` may be an absolute path, a path relative to the text file, a `file:` URL, a `data:` URL, or an `http(s)` image/page URL.
- `effects` contains partial `CellEffects` values to apply to all cells.
- `progress.enabled` ramps effect progress over the specified number of pages.
- `timer.enabled` resets and starts the timer when the tag triggers.

## Remote Image Safety

- Remote storyboard images are loaded through the main-process IPC path, then passed to PixiJS as data URLs.
- Keep same-URL loads deduplicated with in-flight promise caches in both renderer and main. Multiple cells showing the same URL must produce at most one network request.
- Successful remote image loads are cached for the app session. Re-entering the same tag must not re-request the image.
- pixiv-family hosts (`pixiv.net` and `pximg.net`) are capped at 10 distinct image/page URLs per app session.
- The 11th distinct pixiv-family URL must be blocked before network access and must surface a user-visible warning.
- Do not reset the pixiv counter when changing or closing a text file. Only app restart resets it.
- The Text tab must keep showing the current `pixiv requests: n/10` counter from main-process state.
- Never add hard-coded sample pixiv artwork URLs or artwork IDs to code, tests, docs, or commit messages.

## Runtime Behavior

| Event | Action |
|---|---|
| Page advances into a tagged segment | `applyTagToAllCells()` sets `cellTagOverrides[cellId]` and merges `effects` into all cells |
| Page retreats before active tags | `restoreBaseline()` restores the snapshot taken at file load |
| `progress.enabled` | `storyboardEffectProgress` increments from 0 to 1 each page and overrides timer sync in the ticker |
| `timer.enabled` | Timer resets and starts; Auto-advance suspends until timer completes |

## State and Baseline Rules

- `baselineSnapshot` is taken when a text file is loaded.
- Storyboard activity controls cells through `cellTagOverrides`.
- Returning to a reader position before active tags restores the baseline snapshot.
- Storyboard effect progress takes priority over timer-linked effect progress while active.
- Text Reader / Storyboard activity suspends image effect profile auto-application until the text file is closed.

- Keep PixiJS object changes inside `CellRenderer` and `usePixiStage`.
- Update shared types in `src/shared/types.ts` when the storyboard payload shape changes.
- Preserve profile compatibility by merging imported profiles with store defaults.
- Compute structured snapshots outside immer `set()` calls with `get()` when `structuredClone` is needed.
